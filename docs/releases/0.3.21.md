## Cambios

- **`--docker` vuelve a funcionar en el servicio.** La unidad ya no fija
  `TSSH_DISABLE_DOCKER`/`SSH05_DISABLE_DOCKER`; el binario mantiene el
  comportamiento por defecto (contenedores ocultos) y respeta el flag:
  ```sh
  systemctl --user edit ssh05d.service
  # [Service]
  # ExecStart=
  # ExecStart=/usr/bin/ssh05d --ssh-config=%h/.ssh/config --docker
  systemctl --user daemon-reload
  systemctl --user restart ssh05d
  ```
- **Estado vacío más útil en la UI.** Explica `Ctrl+N`, la lectura de
  `~/.ssh/config` y cómo incluir contenedores Docker en el supervisor.

## Verificación ejecutada

- `ssh05d --docker` lista los 6 contenedores del equipo y `ssh05-ui` muestra
  `Hosts (6)`.
- `bun run typecheck`, `typecheck:contracts` y `bun test` (55 pruebas).
- `make verify`: tests Go, contratos, host key, ui-smoke, FRP real y trzsz.

## Límites conocidos

1. Los contenedores Docker siguen siendo opt-in en el supervisor; el cliente
   clásico los muestra por defecto.
2. El extremo remoto de trzsz/Zmodem necesita `trz`/`tsz` o `lrzsz` en `PATH`.
3. GeoIP de ciudad no incluido; ASN/RDAP y país orientativo sí.
