## Cambios

- **Contraseña en el alta de host.** El formulario «Nuevo host» de `ssh05-ui`
  incorpora un campo `Contraseña` opcional (enmascarado). `Ctrl+N` y el menú
  lo muestran también.
- `hosts.create` acepta `password` y escribe en `ssh_config`:

  ```text
  #!! encPassword <codificado>
  #!! encQuestionAnswer1 <codificado>
  ```

  Es el mismo esquema `enc` del cliente clásico y de `ssh05 --enc-secret`; la
  contraseña no se guarda en claro, ni en los perfiles, ni en la auditoría.
- La sesión lee `#!! encPassword` al conectar mediante `getSecretConfig`, por
  lo que la autenticación por contraseña funciona sin volver a pedirla.

## Verificación ejecutada

- Prueba Go: `CreateHost` escribe las entradas codificadas, no contiene el
  texto plano y `DecodeSecret` recupera la contraseña.
- Flujo real por IPC: host creado con contraseña; `ssh_config` resultante
  contiene solo el valor codificado.
- `make ui-smoke`: 91 comprobaciones, incluida la presencia del campo.
- `bun run typecheck`, `typecheck:contracts`, `bun test` y tests Go completos.

## Límites conocidos

1. El esquema `enc` es el heredado del cliente clásico (clave fija): evita el
   texto plano accidental, no sustituye a un gestor de secretos.
2. Para credenciales de alta seguridad, seguir usando SSH Agent/KeePass.
